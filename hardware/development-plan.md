# vbcpet 硬件开发方案

> 从 ESP32-P4 开发板验证到自绘定制板的全流程。
> 前置阅读：[`block-diagram.md`](block-diagram.md)、[`bom.md`](bom.md)、[`pinmap.md`](pinmap.md)、[`power-tree.md`](power-tree.md)。

---

## 总览

```
Phase 0 (1-2 周)           Phase 1 (2-3 周)         Phase 2 (3-4 周)        Phase 3-4 (3-5 周)
Dev Board 验证            KiCad 原理图              PCB 布局布线             打样 + Bring-up
   │                          │                       │                      │
   ├─ DSI 显示              ├─ 01-power             ├─ 叠层 (≥4层)         ├─ 下单打样 (JLCPCB)
   ├─ WebRTC H.264 解码      ├─ 02-p4-core           ├─ MIPI/射频/SDIO 约束  ├─ 分区上电排查
   ├─ 音频回路              ├─ 03-c6-radio          ├─ DRC 通过             ├─ 复用 Phase 0 固件
   ├─ WiFi6 带宽/延迟        ├─ 04-display           └─ 输出 Gerber          ├─ Bring-up 各模块
   └─ 功耗测量              ├─ 05-audio                                   └─ 闭环测试
                            ├─ 06-io-sense          ← 冻结选型
                            └─ 07-usb-debug         ← 落实引脚映射
                               ↓
                            ERC 通过
```

**决策闸门**：每个 Phase 结束有一个 Go/No-Go，确认达标再进入下一阶段。
如 Phase 0 发现 P4 H.264 解码延迟 >300ms 不可接受，则回到架构层面调整方案（降分辨率/改用 MJPEG/换主控）。

## Phase 0 — 开发板去风险验证

**时间**：1-2 周（开发板刚到，即刻开始）
**硬件**：ESP32-P4-Function-EV-Board 或其他 P4 开发板
**目标**：量化所有关键链路的实际数据，冻结选型

### P0-1. DSI 显示出图

| 项 | 内容 |
|----|------|
| 操作 | 跑通官方 LVGL / DSI 示例，确认屏幕正常点亮 |
| 测量 | FPS（目标：1024×600 ≥30fps；800×480 ≥50fps） |
| 记录 | SRAM / PSRAM 占用基线 |
| 产出 | 目标分辨率、帧率、内存占用数据 → 决定 [bom.md](bom.md) DS1 选型 |

### P0-2. WebRTC 视频接收 + H.264 硬解 ⚠️ 最高风险

| 项 | 内容 |
|----|------|
| PC 侧 | 用 `pc-host/host.py --live2d` 或简单 H.264 推流端发送 |
| P4 侧 | `esp_webrtc` + `av_render` 接收 → VPU 硬解 → DSI 显示 |
| 测量 | 端到端延迟（PC 出帧→屏显示，目标 <200ms） |
| 测量 | 码率/带宽需求；丢包下的表现 |
| 长跑 | ≥30 分钟稳定性测试，记录 free_psram 走势 |
| 风险 | P4 作视频**接收/解码**端与官方多数 demo 方向相反，ESP-IDF `av_render` 对接收管线的支持程度未知 |
| 不达标预案 | ①降分辨率/帧率 ②改局部/差分更新 ③调 GOP/码率/jitter buffer ④改用 MJPEG（无硬解但 CPU 可解） |
| 产出 | 延迟/带宽/稳定性数据 → 决定视频方案是否可行 |

### P0-3. 音频回路

| 项 | 内容 |
|----|------|
| 操作 | ES7210 + ES8311 录放跑通（I2C 配置 + I2S 数据） |
| AEC | CH1 回采参考有效 → 放音时上行回声被消除 |
| Opus | 编解码 + WebRTC 音频轨双向 |
| VAD/打断 | 播放 TTS 时用户说话可打断 |
| 延迟 | 单向 <150ms |
| 产出 | 音频可行性确认 |

### P0-4. WiFi6 联网 + 带宽

| 项 | 内容 |
|----|------|
| 操作 | C6 跑 esp-hosted → P4 经 SDIO/SPI 联网 |
| 测量 | WiFi6 AP 下 RSSI / 吞吐 / 丢包率 |
| 判断 | 带宽是否满足 P0-2 测出的视频码率 |
| 产出 | 联网方案可行 + WiFi 天线位置参考 |

### P0-5. 功耗测量

| 项 | 内容 |
|----|------|
| 操作 | 满负载运行（视频解码 + 音频 + WiFi），串入电流表或测 USB 功率 |
| 记录 | 各路电流（core 3.3V / 1.1V / DSI / 音频 / 背光） |
| 产出 | 填入 [power-tree.md](power-tree.md) 实际值，替换预算占位 |

### P0-6. 按键 + 授权回路（可选，加分项）

| 项 | 内容 |
|----|------|
| 操作 | 接 4 个外接按键到开发板 GPIO |
| 闭环 | PC `claude-sdk` 触发工具授权 → DataChannel `permission` → 按键 → `control_response` |
| 产出 | 确认硬件按键→软件授权的物理链路可行 |

### Phase 0 决断

- **Go**：所有 P0 项达标 → 冻结选型，进入 Phase 1 原理图
- **No-Go**：某 P0 项无法达标 → 调整架构（降分辨率/换方案）后重新验证
- 产出文件：`phase0-report.md`（实测数据汇总）

## Phase 1 — KiCad 原理图

**时间**：2-3 周（Phase 0 完成后）
**前提**：Phase 0 选型冻结 + 引脚映射落实

### 1.1 前置准备

1. 安装 KiCad 8.x
2. 导入器件库：
   - Espressif 官方库（ESP32-P4-Module、ESP32-C6-Module）
   - 顺舟 / LCSC 库（ES7210、ES8311、NS4150、VL53L0X 等）
   - 通用器件（电阻电容、连接器、TVS）
3. 根据 Phase 0 使用的开发板 BSP 引脚定义，填充 [`pinmap.md`](pinmap.md) 中所有 `GPIOxx` 占位符
4. 确认 [bom.md](bom.md) 中 5 个 ⚠️ 项

### 1.2 7 张 Sheet 绘制

| Sheet | 文件 | 内容 | 要点 |
|-------|------|------|------|
| 01 | `01-power.kicad_sch` | USB-C 输入、TVS/eFuse、PD sink、DCDC/LDO 树 | 用 Phase 0 实测电流选型 DCDC 额定功率 |
| 02 | `02-p4-core.kicad_sch` | P4 模组、复位/BOOT、晶振、去耦 | 模组内建 PSRAM/Flash，外部仅需电源+去耦+启动配置 |
| 03 | `03-c6-radio.kicad_sch` | C6 模组、SDIO/SPI、天线匹配 | 预留 π 型匹配位，实际调试时调 |
| 04 | `04-display.kicad_sch` | MIPI-DSI FPC 连接器、背光升压、触摸(可选项) | 连接器型号据 Phase 0 选的屏定 |
| 05 | `05-audio.kicad_sch` | ES7210 + ES8311 + PA + 麦阵 + 喇叭座 | 模拟地与数字地分开，单点连接 |
| 06 | `06-io-sense.kicad_sch` | 4 按键、在位传感器×2、TF 卡、RGB LED | 按键加硬件去抖 RC（可选） |
| 07 | `07-usb-debug.kicad_sch` | USB-C 数据(OTG)、UART/JTAG、测试点 | 加 TVS 保护 |

### 1.3 检查项

- [ ] ERC 通过（电气规则检查）
- [ ] 网络标号与 pinmap 一致
- [ ] 电源轨命名与实际电源树一致
- [ ] 模拟/数字地隔离
- [ ] 关键高速信号差分对命名规范（方便 PCB 约束识别）

### Phase 1 决断

- **Go**：ERC 通过 + 同行 Review → 进入 Phase 2 PCB
- **No-Go**：原理图有问题 → 修改后重新 ERC

## Phase 2 — PCB 布局布线

**时间**：3-4 周（原理图完成后）
**工具**：KiCad 8.x PCB Editor

### 2.1 叠层与规则

```
Layer stack (4 层, 1.6mm):
  Top    — 信号 (关键高速走顶层)
  L2     — GND (完整地平面, 不可分割)
  L3     — PWR (3V3_SYS, 1V1_P4_CORE 分区)
  Bottom — 信号 + 少量器件
```

阻抗控制（与板厂确认叠层参数）：
- MIPI-DSI 差分对：100Ω 差分
- USB D+/D-：90Ω 差分
- C6 射频：50Ω 单端

### 2.2 关键布线约束

| 区域 | 约束 | 优先级 |
|------|------|--------|
| MIPI-DSI | 对内等长 ±0.5mm，包地，远离 DCDC | P0 |
| C6 天线 | keepout 区禁铜，50Ω 走线短直，π 匹配位 | P0 |
| SDIO (P4↔C6) | 等长约束，时钟优先 | P0 |
| P4 core 电源 | 大电流短粗走线或铺铜，靠近 BGA 焊盘 | P0 |
| 音频模拟 | 模拟地与数字地磁珠/0Ω 单点连接 | P1 |
| 麦克风 | 差分/对称走线，远离 DCDC/数字 | P1 |
| USB D+/D- | 差分 90Ω，ESD 保护靠近连接器 | P1 |
| 按键/传感器 | 非关键，普通走线 | P2 |

### 2.3 布局顺序建议

1. **先定机械**：屏 FPC 位置、USB-C、按键、喇叭、传感器开窗（3D 外壳模型同步设计）
2. **定 P4 + C6 模组位置**：天线区域靠板边、远离 USB 和 DCDC
3. **定音频**：麦阵远离喇叭（防啸叫）、远离 DCDC（防干扰）
4. **定电源**：DCDC 远离天线/音频，靠近负载
5. **定其余外设**

### 2.4 检查项

- [ ] DRC 通过（含自定义阻抗/间距规则）
- [ ] 差分对等长检查
- [ ] 3D 预览与结构干涉检查
- [ ] 天线 clearance 确认
- [ ] 各主轨大电流路径宽度检查

### 2.5 输出制造文件

- Gerber（RS-274X）
- 钻孔文件（Excellon）
- BOM（含 LCSC 料号 / 替代料号）
- CPL（贴片坐标文件）
- 装配图（丝印层 PDF）

### Phase 2 决断

- **Go**：DRC 通过 → 下单打样
- **No-Go**：布局有问题 → 调整后重新 DRC

## Phase 3-4 — 打样 + Bring-up

**时间**：3-5 周（PCB 下单后）

### 3.1 打样

| 项目 | 建议 |
|------|------|
| 板厂 | JLCPCB / PCBWay（4 层，1.6mm，绿色阻焊） |
| 数量 | 首版 5 片（调试损耗预留） |
| 交期 | 标准 5-7 天 + 快递 |
| SMT | 首次贴核心器件（P4/C6 模组 + 电源 + 音频 + DSI 连接器）；按键/传感器可手焊 |
| 备料 | 关键件各多备 2 个（尤其 P4 模组、ES7210、ES8311） |

### 3.2 上电分区排查（按顺序，不可跳步）

```
Step 1 — 电源
  空板只焊电源部分 → 万用表打各路电压（3V3_SYS / 1V1 / AVDD）
  短路检查（USB VBUS 到 GND 阻抗）
  → 电压不对立即断电排查

Step 2 — P4 最小系统
  焊 P4 模组 + 晶振 + 复位 → 上电 → 串口有输出 (ROM boot 信息)
  → 烧录 hello world → 确认芯片工作正常

Step 3 — C6 联网
  焊 C6 模组 → 烧 esp-hosted 固件 → P4 经 C6 联网 → ping 通 PC
  → RSSI 与 Phase 0 数据对比

Step 4 — DSI 显示
  接屏 → 跑 DSI 示例 → 确认出图 → FPS 与 Phase 0 对比

Step 5 — 音频
  焊 ES7210 + ES8311 + PA + 麦 + 喇叭
  → I2C detect → 录放测试 → AEC 效果

Step 6 — 外设
  按键 / 在位传感器 / RGB LED / TF 卡 → 逐个功能测试

Step 7 — 闭环
  PC → WebRTC → 自绘板 (视频+音频+DataChannel) → 按键授权回路
```

### 3.3 Bring-up 记录

每个 Step 完成后记录：
- 实测数据（电压/电流/波形/FPS/延迟）
- 问题与修复（配图）
- 原理图/PCB 需要改的地方（记入 v1.1 修订清单）

## Phase 5 — 迭代与量产考虑（开放性）

Phase 5 偏后期，此处列出方向性指引，具体实现随进展调整。

### 改板触发条件

- 原理图 Bug（连接错误、电源时序问题）
- 布局问题（天线匹配差、音频噪声、散热不足）
- 器件断货需要替代料号
- 增加新功能（如之前砍掉的 Qi 充电、电池）

### v1.x 迭代方向（优先级可调）

| 优先级 | 改动 | 理由 |
|--------|------|------|
| 高 | 修正 Bring-up 发现的所有硬件 Bug | 稳定性前提 |
| 中 | 增加外壳结构配合（螺丝孔、FPC 限位） | 外观可用性 |
| 中 | 天线匹配调优（根据实测） | WiFi 性能 |
| 低 | 增加电池管理（LiPo + 充电 IC） | v2 便携化 |
| 低 | 增加 Qi 无线充线圈 | 手机充电底座 |
| 低 | 增加 HDMI / LCD 副屏接口 | 调试/扩展 |

### 量产考虑（远期）

- BOM 成本控制在 ¥150-250（不含屏/外壳）
- 关键器件双货源（尤其 P4 模组、音频 codec）
- CE/FCC 认证（WiFi/BLE 射频）— 量产才需要
- 外壳开模 vs 3D 打印验证

## 时间线估算

| 阶段 | 时间 | 依赖 |
